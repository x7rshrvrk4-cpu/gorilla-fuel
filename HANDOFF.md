## 4. Core system map

### Scan / ingest pipeline (barcode → data → score → cache)
- **Live scan UI:** `app/scan/page.tsx` → `app/scan/ScanClient.tsx` (client). Camera/decoder is `app/scan/components/BarcodeScanner.tsx` (ZXing — **off-limits**, do not touch). Deep-link entry: `/scan?b=<barcode>` (ScanClient reads the `b` param).
- **Lookup order (verified components):** `lookupProductCache()` (`app/scan/lib/productCache.ts`) → live Open Food Facts (`app/scan/lib/openFoodFacts.ts`: fetch + `scoringContext()` + `resolveIngredientsText()`) → other live sources / curated / community fallbacks (see §5) → `computeScore()` → `upsertProductCache()` (fire-and-forget; never throws).
- **Bulk import:** `scripts/import-canada.ts` (OFF v2 `/search`, `countries_tags_en=canada`, `sort_by=created_t`, 6.5 s/page, batches of 200) and `app/api/admin/import-off/route.ts` (cgi `search.pl`, admin-key gated). Both map raw OFF → cache rows via **`buildOffRow()`** in `app/scan/lib/productClassify.ts`, which runs the exact same `computeScore()` + gate path.

### Scoring engine (`app/scan/lib/scoring.ts` — do not modify without benchmark re-run)
- **Composite weighting (line 2300):** `finalScore = round(effectiveNutritionScore*0.6 + effectiveAdditiveScore*0.3 + organicBonus)`. The "10%" is an **organic bonus only** (0 or +10; never a penalty), so it's 60% nutrition / 30% additive / +10 organic — not three equal legs.
- **`additivesUnverified` cap (lines 2238–2243):** when there's no ingredient text **and** no `additives_tags` **and** the row is not inferred-sweetener / plain-water / whole-food / pure-oil exempt → `effectiveAdditiveScore = min(x, 50)`. This is the "incomplete label is scored conservatively, not clean" doctrine.
- **`isWholeFood()` (line 1188) disqualifiers:** branch 0 is a **juice/drink name disqualifier** — `JUICE_NAME_PATTERN = /\b(jus|juice|nectar|smoothie|boisson|drink|limonade|lemonade|punch)\b/i` returns false immediately (so "Jus …" juices are never whole-food-exempt). Then NOVA-1 → true; exact produce category-tag membership (with sugar/salt guards, 18 g fruit / 12 g veg sugar ceilings); and a name-lexicon + raw-produce macro signature (protein ≤5, sat-fat ≤0.5, salt ≤0.2, sugar present & ≤25) path, all blocked by `PROCESSED_NAME_PATTERN`/`PROCESSED_CATEGORY_PATTERN`.
- **Per-serving band penalties (`scoreNutrition`, from line ~1636):** when serving data exists — sugar/serving: −10 (>5), −15 (>12), −35 (>20), −40 (>30); sat-fat/serving: −8/−15/−22/−35; sodium/serving (mg): −5/−12/−20/−28. Plus per-100g concentration penalties and NOVA-4 (caps nutrition at 45). Two severe flags → nutrition hard-capped ≤55; incomplete critical nutrients → ≤45.
- **`gradeFromScore()` (line 1348) — 4-tier:** **Poor 0–39 · Moderate 40–64 · Good 65–84 · Excellent 85–100.** (Note: some older inline comments still reference a "75 Excellent" threshold — that is stale; 85+ is current.)

## 6. Regional / provincial handling

- **`countries_tags` capture (Phase-1 UK expansion, commit `37ff9f6`):** `buildOffRow()` now reads OFF `countries_tags` and stores it JSON-encoded (same convention as `categories`); `import-canada.ts` requests the field; `productCache.ts` types + documents the additive `ALTER TABLE … add column countries_tags text` migration. **The column is not yet provisioned in prod** (`42703` at snapshot) — capture is inert until the one-line migration is run in the Supabase SQL editor.
- **Canada-first `/top` filter (`app/lib/topProducts.ts`, `getTopOverall`):** drops UK-tagged rows from the merit ranking — keeps a row when `countries_tags` is NULL (all pre-Phase-1 rows), OR contains `canada` (dual-market), OR doesn't contain `united-kingdom`. It is guarded by a **4-way graceful fallback** (drops the country clause, then the `display_name_en` select) so `/top` never breaks whether or not the column exists. Search and scan do **not** call `getTopOverall`, so UK/any-origin products stay fully searchable/scannable.
- **Provincial adapters:** there is **no general provincial-adapter abstraction.** What exists is **product-specific alcohol handling**: a **BC Liquor** staging table + `/bc-liquor` route + ingest (`scripts/ingest-bc-liquor.ts`, `seed-curated-alcohol.ts`), and the curated alcohol rankings are honestly labeled **Ontario** (commit `2772542`), not national. There is a **read-only UK-food ingest dry-run tool** (`scripts/uk-food-dryrun.ts`) but **no UK data has been imported** (the actual ingest is deferred pending an ingredient-completeness / `states_tags` strategy).

## 7. Known gotchas

- **~89% null-ingredients coverage gap.** ~41,140 / 46,074 cache rows have `ingredients_text = NULL` (~40,952 are scored food rows). Code documents this as "~84.5% data-blind" (`dataConfidence.ts`). Consequence: additive detection has nothing to scan on most rows, so they hit the `additivesUnverified` 50 cap and are scored on macros alone. The durable fix is the OCR read-back loop (§8), not scorer tuning.
- **`display_name_en` vs `product_name` split.** The **scorer reads `product_name`**; display surfaces render `display_name_en ?? product_name` (see the comment in `topProducts.ts`: *"Never read by scoring — the scorer reads product_name"*). `display_name_en` was backfilled (Phase A: OFF `product_name_en`, ~212 rows; Phase B: a conservative FR→EN resolver, ~91 rows) and **never** feeds scoring. Don't "fix" a French score by editing `display_name_en`.
- **`isDataBlind` vs `additivesUnverified` condition split (partially reconciled in `35a9797`).** The scorer's `additivesUnverified` cap fires on a **looser** condition (no ingredients + no additive tags + not whole-food/water/oil exempt) than the original `isDataBlind` (which additionally required no NOVA **and** no categories). That left ~2,334 capped-but-categoried rows getting the 50 cap with **no** disclosure strip / OCR panel. `35a9797` added `additivesUnverifiedForDisplay(product, additiveScore)` in `dataConfidence.ts` (gates on `additiveScore <= 50`, which mirrors the cap and auto-excludes exempt produce) and pointed `ProductResultCard`'s strip + OCR panel at it. `isDataBlind` itself is left intact for its documented "knows nothing but macros" purpose.
- **Silent-failure by design.** Cache reads/writes (`productCache.ts`), `getTopOverall`, `getCuratedPicks`, and the search route all **swallow errors and return `[]`/degrade gracefully** — a Supabase outage yields empty rails, not a crash. Good for resilience, but means data problems can hide (a broken query looks like "no results"). The live-scan `upsertProductCache` is fire-and-forget.
- **Stored scores can be stale.** `gorilla_score` is persisted; scorer changes only take effect after a targeted recompute (the `recompute-*` tools) or re-import. A product observed at an old score may predate a scoring-doctrine change (e.g. pre-`additivesUnverified` / pre-per-serving-sugar). Recompute batches are logged to `gorilla_score_corrections`.
- **Live-scan upserts don't set `countries_tags`** (ScanClient builds its payloads inline; the scanner is off-limits), so scanned-in rows stay origin-untagged like the pre-Phase-1 catalogue — fine for Canada-first, but not a UK-tagging path.

## 8. Validation / curation infrastructure

- **Benchmark test (deploy gate):** `scripts/test-curated-scores.ts` asserts all 12 `CURATED_SCORE_CONSTANTS` (`curatedScoreConstants.ts`) via `lookupCuratedScore` + `applyScoringGate` (must be `gorilla-verified`). Runs in `prebuild`, so a score drift **blocks the deploy**. Update expected scores in `curatedScoreConstants.ts`, never in the test.
- **Review sheets (`data/`, read-only):** `scripts/gen-curation-review.ts` (+ untracked `_gen_*` scratch generators) write brand-grouped / avoid / cheat / top candidate markdown to `data/` against **current** live scores, reusing the ingest tool's SUPP + `canonKey` logic. These are **generated artifacts**, not code.
- **`--write` re-run workflow:** edit `data/curated-picks-input.json` → dry-run `node --env-file=.env.local scripts/ingest-curated-picks.mjs` (prints the populate plan + band-drift warnings) → `--write` to upsert into `curated_picks` (`on_conflict=barcode,tier`, needs the service key).
- **OCR capture flow (Phase 0):** `app/scan/components/OcrCapturePanel.tsx` (shown on unverified-additive rows) → `app/scan/lib/ocrIngredients.ts` (client-side Tesseract → parse → user-confirm). **Phase-0 safety invariant:** writes **only** to the `community_ocr_ingredients` **staging** table (`verified=false`, admin-review); it **never** writes `gorilla_product_cache.ingredients_text` and **never** calls `upsertProductCache`, so an OCR/parse bug cannot move any live score. The "scan-time read-back loop" (OCR'd ingredients feeding a live re-score) is **deliberately not built**.
- **Tuning knobs — DATA vs CODE:**
  - **DATA** (no code change): `data/curated-picks-input.json` — `approvedItems/cheatItems/avoidItems` (explicit pinned barcodes; currently 0/49/49), `approvedBrands/cheatBrands/avoidBrands` (allowlisted brands), `skipItems`. Change the curated sets here + re-run `--write`.
  - **CODE** (change + benchmark + build): the **band cutoffs** and **precedence** live in `scripts/ingest-curated-picks.mjs`; all **score math** lives in `app/scan/lib/scoring.ts`; the **12 pinned expectations** in `curatedScoreConstants.ts`.

## DDL caveat (read before trusting the schema)

There is **no migrations directory and no direct DDL connection** in this repo — Supabase tables are provisioned **manually in the Supabase SQL editor**. Several tables document their `create table` in a leading comment of their lib file (`gorilla_product_cache` + `gorilla_import_log` in `productCache.ts`; `barcode_aliases` in `barcodeAliases.ts`; `community_ocr_ingredients` in `ocrIngredients.ts`; `community_alcohol_products` in `communityProducts.ts`). **`curated_picks`, `bc_liquor`, `gorilla_score_corrections`, `fuel_audit_log`, `missed_scans`, and `scan_notifications` have no DDL found in the repo** — their exact schemas/constraints live only in Supabase and were **not verifiable here**. Notably, whether `curated_picks.tier` has a CHECK constraint (and its allowed values) could not be read from the repo; it is inferred to allow `avoid` only because 54 `avoid` rows exist live.
